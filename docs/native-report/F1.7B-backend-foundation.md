| Component | Responsibility |
| --- | --- |
| Config / Capability | Explicit opt-in configuration; dedicated key ring; versioned, unambiguous HMAC-SHA256 context; independent server salt; canonical 32-byte bearer; persisted verifier; explicit revocation; hash-only completed verification |
| Ledger | Native session, item, upload-key alias, quota and operation ledgers; UNIQUE identities; named-lock exclusion; optimistic lifecycle versions; atomic cumulative byte counters |
| Storage | Server-created exclusive files, 0700 directories/0600 originals, canonical realpath/root and symlink checks, private staging and deterministic promotion/reconciliation |
| Validator / worker | Byte cap/checksum, signature/MIME and extension agreement, image dimensions and pixel limit, static container checks, full decode in constrained GD CLI subprocess |

| Persistence / linker | Wraps the frozen F1.4 under its existing native submission lock; UUID-to-numeric translation only inside private linker; promotion, final row reconciliation, early-event-return verification and exact-set receipt |
| Fence | Provenance from final media, canonical native report, event metadata and native ledger; blocks every legacy approval/materialization/publication path, including published-event recovery |
| Cleanup | Hourly bounded cleanup and durable intent recovery; current state/version rechecked under lock; active writer/operation locks respected; selected pinned/bound originals protected |

Selected manifests may contain a subset of accepted uploads. Excluded originals remain unbound and removable until upload expiry, and are collected at the hard orphan TTL even if their session is pinned/committed. Selected evidence cannot be removed by anonymous clients. No global checksum deduplication.

Lock ordering: short preflight admission/session locks are released before F1.3; F1.4 subsequently owns the native submission lock and acquires session then sorted media UUID locks. Upload operation/writer locks do not enter the native lock. Byte accounting is an independent atomic quota update and does not invert writer/session lock order. Cleanup never treats lease expiry alone as proof that a writer has stopped.

Recovery A–E preserves the same submission/report/event/manifest. The deterministic final target and lookup reconcile both rename-before-insert and insert-before-mapping crashes. Failed DB lookups are errors, never evidence that a final row is absent. Completed replay checks canonical fingerprint, verifier, receipt, exact mappings and allowed later review states without filesystem reads, persistence calls, TTL renewal or moderation changes. Existing transport request auditing/rate control remains F1.5 behavior.

Until native review/derivatives exist, native media publication is intentionally blocked even after a receipt; originals stay private. Legacy WPForms remains `received` and continues through its legacy publication path. No native derivative is produced in this task.

## API

All media requests use `X-BadAround-Media: badaround-report-media/v1`; all owner operations use `X-BadAround-Media-Capability`. HTTPS and exact same-origin/Fetch Metadata expectations apply. Admin cookies are not an ownership source. Private-route CORS headers are removed, including errors/OPTIONS; responses use no-store/private and nosniff.

| Route (under `/wp-json/badaround/v1`) | Input / result |
| --- | --- |
| POST `/report-media-sessions` | JSON `submission_id`, canonical base64url `creation_nonce`; 201 new / 200 exact replay; session, capability, immutable deadlines, effective limits/codecs |
| POST `/report-media-sessions/{session}/items` | Multipart `file`, `client_upload_id` only; 201 accepted / 200 duplicate; canonical descriptor; browser MIME/size and Content-Length are not authoritative |
| GET `/report-media-sessions/{session}` | Owner session state, descriptors and receipt; no original/path/filename/EXIF/capability |
| GET `/report-media-sessions/{session}/items/{media}` | Owner item status; foreign/unknown media share the same error |
| DELETE `/report-media-sessions/{session}/items/{media}` | 200 removal tombstone; idempotent; physical deletion precedes quota release; selected pinned/bound originals blocked |
| POST `/reports` | Original JSON/marker; only valid nonempty media adds capability preflight; media marker is not required; original F1.5 success shape |

Limits: 5 accepted images × 5,242,880 bytes, 25 MiB maximum accepted total; ≤10,000 px per side and ≤25,000,000 pixels. Upload/remove TTL 2h, first commit and hard unbound TTL 24h, interrupted lease 15m. Every received stream, including duplicate/invalid bytes, counts toward quotas. Replay readers consume persistent concurrency admissions too. Terminal sessions/receipts are not silently deleted; continued retention/capacity policy is an operational concern.

Default opt-in limits are centralized: session creation 12/IP/900s; upload attempts 30/IP/900s and 20/session lifetime; validation failures 10/IP/900s and 5/session lifetime; bytes 100 MiB/IP/900s and 100 MiB/session lifetime; two operations/session and IP; one global decoder; 1,000 active sessions and 10,000 total session identities. Temporary/archive budgets default to **zero**, not an assumed 1 GiB. Synthetic tests alone configure a fixture budget.
