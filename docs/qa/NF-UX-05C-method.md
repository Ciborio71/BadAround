# NF-UX-05C responsive evidence method

Application candidate: `d0ac50bf4866b326943f3f4487b49fbe3d878d7b`. Staging only; no application/security changes, deploy, merge, production activity, DB write or submission.

The user expressly authorizes responsive equivalence evidence: fresh Chromium at 320/390/1440, exact remotely verified candidate bytes, plus the already completed deployed-browser functional certification NF-UX-05B.

The runner uses strict, identity-verified FTPS RETR only for custody. It does not use staging HTTP. Five Native files, Core/backend/contract (33 baseline paths total), plus 15 rendering dependencies are compared byte-for-byte to their certified Git objects. Astra CSS and frontend JS are read from the same remote theme and saved with SHA-256 provenance.

The exact candidate header.php, footer.php, page-segnala-evento.php, Native shell.php and step.php execute under isolated PHP WordPress API stubs. Their application source is not modified. Actual deployed configuration, body classes, inline CSS, breakpoint script, Astra configuration and footer scroll-to-top element are captured from the ordinary authorized cloud browser. The server config is injected as explicitly allowed by this task. Rendering fields, labels/categories, steps, conditional metadata and emergency metadata remain unchanged. Only REST endpoint origins are rebased to the intercepted isolated origin and the external Places key is blanked; external GEO/API behavior is outside this responsive-only task.

Every Chromium request is intercepted and fulfilled from verified local bytes or aborted. No staging HTTP request, public-network browser fallback, WAF bypass or submission is used. Only GET is permitted by the route guard. Profile setup uses the existing in-memory model/render event to prepare five representative states; subsequent dependent activation, focus, keyboard and back/forward actions use actual application handlers. No injected CSS, replacement Native markup, patched wizard/model/errors, alternative renderer or semantic evaluator is used.

Five profiles: civic_waste; property_theft with access/stolen-item specifications and damage; animal_missing with animal Altro; hazard_fire_or_smoke with immediate danger unsure/damage; vehicle_stolen with fixed reward and authority Altro. Exactly 15 width/profile combinations. The test measures document overflow, visible control horizontal bounds, dependent autofocus viewport/occlusion, CTA bounds and pairwise separation, keyboard exit/reachability, back/forward navigation, summary geometry and summary submit reachability without activating submit. One full-page screenshot per successful combination is retained, at most 15. Full-page screenshots retain sticky elements at the current capture scroll offset; viewport geometry checks are made before capture.

Initial harness validation runs are not application failures and are not counted as completed responsive evidence: run 39851700233 correctly hit the unchanged media same-origin guard because the isolated page still had staging REST URLs; run 39852332216 passed the first 320px layout/navigation assertions but the harness omitted the Astra footer hook expected by the unmodified parent script. Transport rebasing, the exact captured footer hook and complete conditional test inputs were added only to QA files. Run 39852946260 then passed simple/complex 320px cases and exposed a QA selector mismatch: the animal control is a native nine-option select, not a radio group. The harness selector was corrected to the actual control; no application change was made to obtain a green result. Run 39853400486 exposed a second harness assumption: the generic native animal select preserves native keyboard focus rather than invoking the custom card auto-next handler. Its specification was already visible; the test now verifies normal Tab reachability. Authority and danger card paths still verify their existing auto-focus, including notice viewport geometry.

NF-UX-05B remains the source for the full semantic/real-staging certification, existing submissions #69/#345, #70/#346, #71/#347, and all prior protected fixtures. This task does not repeat those suites or create replacement fixtures. No new temporary staging QA endpoint is installed.
