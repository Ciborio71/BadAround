# F1.9 — Native Report Wizard Manual Browser QA Checklist

Candidate-only checklist. No deploy is authorized by this document.

## Desktop

Run at 1440 px and 1024 px widths.

For each Step 1 → 7 verify:
- no horizontal page/form overflow;
- heading, intro copy, labels, help text, controls and buttons use one coherent font stack;
- control heights, border radii and vertical rhythm are consistent;
- focus ring is visible and not clipped;
- hidden progressive-disclosure fields occupy no space;
- Continue/Back/Submit remain stable and do not jump horizontally;
- step transition focuses the new step heading;
- transition scrolls only when necessary and leaves the heading below the sticky header;
- progress indicator shows current/completed/future states and only the active item has aria-current="step".

Step 5:
- choose No: continue/review remain available and no media request is required;
- choose Yes with service unavailable: controlled error copy is shown, not a crash/blank state;
- accepted local preview, progress, retry and remove controls remain aligned;
- incomplete media blocks final submit;
- changing away from Yes while an active selection exists remains blocked by the frozen F1.7 behavior.

Step 7:
- review is grouped into readable sections;
- dt/dd label/value pairs align;
- long values wrap without horizontal overflow;
- field help remains secondary to the value;
- accepted media previews and unresolved media warnings remain distinct;
- displayed values match the values entered in the wizard.

## Tablet

Run at 768 px.

Verify Step 1 → 7:
- two-column progress layout wraps without horizontal scrolling;
- fields, fieldsets and choice cards fit the viewport;
- review changes to one-column label/value layout;
- textarea/select/input widths remain within the wizard;
- navigation buttons remain reachable and correctly sized;
- sticky navigation does not cover the focused field/heading.

## Mobile

Run at 430 px, 390 px and 360 px.

For each width and Step 1 → 7 verify:
- no horizontal scrollbar;
- progress wraps inside viewport;
- labels do not overflow;
- choice-card text wraps;
- all controls retain >=48/50 px touch target where applicable;
- Back/Continue/Submit do not clip or overlap;
- sticky actions do not cover validation messages;
- step heading is visible after Continue/Back;
- focus is not placed underneath the header;
- review sections and media cards remain single-column;
- filenames, error text and long review values wrap safely.

## Keyboard

Using only keyboard, repeat Step 1 → 7:
- Tab order follows visual/document order;
- Shift+Tab works in reverse order;
- focus indicator is visible on inputs, selects, textarea, choices and buttons;
- Space toggles checkbox/choice inputs;
- Enter/Space activate buttons where native behavior applies;
- hidden/disabled fields do not receive focus;
- Continue moves focus to the next step heading;
- Back moves focus to the previous step heading;
- validation failure moves focus to the error summary;
- activating an error-summary item moves focus to the related field;
- Step 7 and final submit are reachable without pointer use.

## Error paths

Required field:
- leave a required field empty and Continue;
- wizard remains on the correct step;
- error summary is focused;
- field has aria-invalid="true";
- visible field message is present and linked through aria-describedby.

Conditional field:
- trigger a conditional field, leave it invalid/empty and continue;
- conditional field is visible, enabled and reported;
- after changing the parent choice so it becomes hidden, the hidden field no longer occupies space and does not enter the effective payload.

Media unavailable:
- choose Yes and provoke/service-unavailable state;
- clear controlled message is visible;
- no raw exception, token, path or response body is exposed;
- incomplete media blocks submit;
- choose No on a clean/no-selection state and confirm the no-media path remains usable.

Submit validation reject:
- submit a syntactically valid wizard state that receives a structured validation reject;
- summary shows safe presentation text;
- correctable field error can be focused;
- no duplicate submission is created by UX interactions;
- retry semantics remain those frozen by F1.5/F1.7.

## Acceptance

Browser QA is PASS only if all applicable checks above pass at:
- 1440
- 1024
- 768
- 430
- 390
- 360

Record browser/version, viewport, failed check (if any), screenshot/evidence reference and whether failure is visual-only or functional. Any functional-contract issue is a STOP for F1.9 rather than a styling workaround.
